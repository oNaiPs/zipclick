How fast ZipClick is

The same 337 MB of files, packed in seven archive formats, extracted by ZipClick and by the tools people already use on Windows. Shorter bars are faster.

For .zip files, which is what most people get, ZipClick is faster than Windows' own Extract All and WinRAR, and slower than 7-Zip, Bandizip and tar.exe. For .tar.zst it is the fastest. For .rar and .tar.xz it is the slowest, and for .7z only WinRAR is slower: ZipClick decodes those formats with code written in Go on a single core, where 7-Zip and Bandizip use optimised C and assembly on several cores. For 1 GB of files in a .7z that means about 17 seconds instead of 4.

How it was measured

  • The files: 204 files, 337 MB in total. 200 text files of about 1 MB, which compress well, and four 25 MB files of random data, which don't, like photos or video.
  • The computer: Windows 11 25H2 in a virtual machine with 8 cores of an Intel Core i5-12600H and 6 GB of memory, with Microsoft Defender on.
  • The programs: ZipClick 0.4.1, 7-Zip 26.04, WinRAR 7.23, Bandizip 7.47, and the tar.exe, Extract All and Expand-Archive that come with Windows 11.
  • Each program extracted each archive three times and the table shows the middle time, from start until the last file is written. Every run was checked afterwards: all 204 files, all 337,415,044 bytes.
  • Windows Extract All was measured through the same Shell copy the menu item uses. WinRAR ran its background extraction, as from its context menu.
  • 7-Zip decodes .7z and .xz on several cores when the archive was written in blocks, as these were.
  • Bandizip only unpacked the .tar from inside the .tar.xz and .tar.zst, so it is left out of those two.
  • Measured on 18 October 2026.
